# SIBiLS MkDocs theme

A standalone MkDocs theme for sibils.org (`theme: {name: null, custom_dir: theme}` in
`mkdocs.yml`). It needs no theme package, no CDN and no build step: run `./serve` from the
repository root and edit the files; the preview reloads (`watch` in `mkdocs.yml`). The look follows the SIBiLS web applications: red band with the white wordmark,
white sub-bar with the documentation sections.

## Files

| `home.html` | Home page (`template: home.html` in `docs/index.md`): intro band from the front matter, collection counts, content |
| `404.html` | "Page not found" (a static template, see `static_templates` in `mkdocs.yml`) |
| `partials/head.html` | `<title>` (the page's H1), description (front matter, else the `{ .lead }` paragraph, else the site's), canonical URL, Open Graph and Twitter cards, icons, the script that applies the light/dark theme before the first paint |
| `partials/jsonld.html` | schema.org description of SIBiLS, home page only. Its service channels are the SIBiLS apps of `extra.apps` |
| `partials/header.html` | Red band: the wordmark, a link to the home page. Unlike the apps' own band, it does not list the SIBiLS apps: the Services section, the home page and each service page link to them |
| `partials/subbar.html` | Site title, the top-level nav sections, search button, theme toggle, menu button (below 1024 px). Once the red band has left the screen, the title shows the wordmark's letters on a red chip in place of the text "SIBiLS Documentation" (see "Header" below) |
| `partials/sidebar.html`, `toc.html`, `breadcrumb.html`, `pager.html` | Navigation around the content |

| `partials/counts.html` | Home page collection counts: a round lower bound of each count from `config.extra.sibils` (set by `hooks/sibils_data.py`), in grey and read as "at least …" by screen readers, until `js/counts.js` replaces it |
| `partials/footer.html` | Partner logos (`extra.partners`), licence, How to cite link (Publications page, `#how-to-cite`), contact, privacy link (About page, `#privacy`), source link |

| `partials/macros.html` | Navigation helpers, URL resolution for front-matter links, icons |

| `css/pygments.css` | Syntax colours, generated by `tools/build_pygments_css.py` |

| `js/search.js` | Search dialog over `search/search_index.json` (written by the MkDocs `search` plugin) |

| `js/vocab-filter.js` | Vocabularies page only (`main.html` loads it when the content has the empty `div.vocab-filter` written by `hooks/sibils_data.py`): the "Annotation type" filter of the vocabulary tables. See "Vocabulary filter" below |

MkDocs copies every file of this folder to the site except templates (`*.html`), Python files and
this README.

## Header

- The red band (`partials/header.html`) scrolls away with the page; the white sub-bar
  (`partials/subbar.html`) sticks to the top of the screen.
- While the band is on screen, the sub-bar title is the text "SIBiLS Documentation". Once the
  band has left the screen (an `IntersectionObserver` in `js/theme.js` sets `.is-stuck` on the
  sub-bar), the title is the wordmark's letters, white on a red chip, in place of the text. So
  one SIBiLS logo is on screen at a time. The switch is instant (no transition) and moves
  nothing: both states share one grid cell, as large as the larger state. From 420 px the text
  is the larger one from an 11 px default font size up (181 px at 16 px, against 118 px for the
  chip), so the bar and its wrapping are those of the text alone; below 420 px the cell is the
  chip's width.
- The chip is 36 px tall, like the search button, so the bar keeps its 53 px. The letters are
  20 px tall; the red around them (8 px of padding, 8.4 px to the visible letters) is at least
  the size of the wordmark's badge (6.1 px, the small square at its top right), the clear space
  the SIB brand book asks for around a logo (the size of its emblem).
- `img/sibils-wordmark-letters-white.png` is cut from `img/sibils-wordmark-white.png` at full
  resolution, rows 2 to 116 and columns 4 to 587 (the letters and the badge, and the source's
  own faint halo, alpha 5 of 255, around them; the descriptor line starts at row 147). If the
  wordmark changes, cut it again:

      ffmpeg -i theme/img/sibils-wordmark-white.png -vf crop=584:115:4:2 -frames:v 1 \
        theme/img/sibils-wordmark-letters-white.png

- The link is named by its text, "SIBiLS Documentation", in both states (the chip is
  `aria-hidden` and its image has an empty `alt`). Without JavaScript the chip never shows.
  Below 420 px the title is "SIBiLS" alone (the rest is visually hidden). The pointer and the
  focus ring follow the visible state, not the whole cell.
- Forced colours (Windows contrast themes): the chip, and the band's wordmark with an 8 px red
  edge, keep their red ground (`forced-color-adjust: none`); otherwise the white letters would
  sit on the system background.
- Anchors and focused elements land 16 px below the sticky sub-bar (`scroll-padding-top`), and
  the sidebar and "On this page" stick 24 px below it (`--sticky-top`). Both use `--bar-h`, the
  bar's measured height, which `js/theme.js` keeps up to date with a `ResizeObserver`: the bar
  is 53 px (`--subbar-h`, also the value without JavaScript) but wraps to two rows with a large
  default font size. The "On this page" highlight uses the same height. An inline script right
  after the bar sets `--bar-h` a first time, before the browser scrolls to the anchor of the
  address. The page above the anchor can still change during the load (web font, `js/theme.js`)
  and Firefox does not always follow it, so `js/theme.js` scrolls to it once more at `load` if
  it is out of place, unless the page has been scrolled in the meantime (input events, or a
  scroll that takes the anchor away from its place while it stays at the same place in the page).
- Tab into a control of the stuck sub-bar does not scroll the page (`scroll-margin-top: -100vh`
  while `.is-stuck`); without it Chromium and WebKit scroll up to "show" a control that lies in
  the `scroll-padding-top` area, and bring the red band back.
- The menu (`partials/drawer.html`) follows the order of the wide layout: the six sections (the
  sub-bar), then the pages of the current section under its name (the sidebar). It opens at its
  top when the current page fits below the sections; otherwise it scrolls as little as needed to
  show the current page (and its headings, as long as the current page stays on screen). It
  closes when the page is left (`pagehide`), so that Back does not bring the page back from the
  back/forward cache with the menu open.

## Navigation rules

- The sub-bar lists the top-level entries of `nav`; a section links to its first page.
- The breadcrumb lists the sections above the page. A section whose first page is the current
  page is plain text, not a second link to the page.
- The left sidebar lists the pages of the current top-level section. A top-level page without a
  section (Overview, Publications) has no sidebar.
- A nav section whose first child is a page **without a title** (for example
  `- developers/biodiversitypmc/index.md` under "BiodiversityPMC") uses that page as its landing page:
  the section label links to it and the page is not listed again.
- "On this page" appears when a page has at least two `##` headings and the window is at least
  1200 px wide. Its column is reserved on every page, so the main column has the same width and
  position on all pages.
- Front matter `hide: [navigation]` and `hide: [toc]` remove the sidebar or "On this page".
- Wide pages (`layout is-wide`): no "On this page" column and a main column up to the full
  width (layout up to 1600px). Automatic for pages containing `<swagger-ui`; front matter
  `wide: true` / `wide: false` overrides it. Paragraphs keep their 40rem reading width.
- The ids of theme elements start with `__` (`__content`, `__search-dialog`...), so that they
  cannot collide with the ids of headings (a `## Content` heading gets `id="content"`).

## Colours

Colour tokens are CSS custom properties at the top of `css/sibils.css`, once for light and twice for
dark (the `data-theme="dark"` attribute set by the toggle or the system preference, and the system
preference alone for visitors without JavaScript). Text colours are at least 4.5:1 on their
backgrounds and borders that identify a control at least 3:1. If you change a token, check the
pairs again; `tools/build_pygments_css.py` does it for the code colours:

    ./venv/bin/python theme/tools/build_pygments_css.py

## Collection counts

The home page is built with approximate counts: each count of the build, rounded down to two
significant digits (`approximate()` in `hooks/sibils_data.py`), in the `--approx-ink` grey
(at least 4.5:1 on the intro band, in light and dark), with a visually hidden "at least " before
it. `js/counts.js` then fetches `count_url` once: a simple CORS GET (no custom header, so no
preflight), without cookies, timeout 3 seconds. For each collection whose count is an integer
not below `data-min` (`live_min`: half the round number, so a 0 or a partial count is not shown)
it writes the exact number (`Intl.NumberFormat('en-US')`, the format of the build) and removes
the grey and the hidden text, at once (no transition). Anything else (no answer, HTTP error,
CORS refusal, invalid JSON, `success` not `true`, a missing or invalid count) leaves the
approximate values: no message, no retry, no `aria-live` announcement. DM Sans has no tabular
figures and its "0" is wide, so the round numbers are a little wider than the exact ones. Where
the numbers are right-aligned, the number fills the rest of its line; from 640 to 1023 px the
five columns are equal (`flex: 1 1 6.5rem`) and never narrower than their text, so a larger text
size or text spacing wraps the row instead of making the numbers overlap. In both layouts the
exact number does not move the layout. No other page loads the script.

## Vocabulary filter

On the Vocabularies page, `hooks/sibils_data.py` writes an empty `div.vocab-filter` above the
tables and the type of each vocabulary in a `data-type` attribute on its row anchor, for example
`<span id="chebi" data-type="chemical">`. `js/vocab-filter.js` turns the div into a search
landmark named "Vocabulary filter", with the select "Annotation type": "All types", then each
type exactly as the API returns it, with its number of vocabularies, sorted by lower case.
Choosing a type hides the rows of the other types, a table left empty together with its `###`
heading and shared paragraph, a `##` category left with no table, and their entries in "On this
page" and in the sidebar or menu drawer. The hiding (`.is-filtered-out`) applies on screen only
(`@media screen`): print shows every vocabulary, and so does the page without JavaScript, where
the div stays empty and takes no space. With JavaScript, the empty div already has the height of
the filled filter (`--vocab-control-h`: 40 px, 44 px on touch screens; plus the label's line
under 640 px), so the tables do not move when the deferred script fills it: if the layout of the
filter changes, change that height too. While a type is chosen, a "Show all N vocabularies"
button clears it and returns focus to the select.

The chosen type is kept in the address, `?type=chemical`, written with `replaceState`: a closed
select changes on every arrow key, and Back should leave the page rather than step through the
types. Not `?q=`, which opens the site search (`js/search.js`). A link to a row or heading that
the filter hides clears the filter; choosing a type that hides the target of the address drops
the `#fragment`. A type in another case or with spaces around it (`?type=Chemical`) is read as
the type it names, and written back as that type; an unknown type shows everything. Screen
readers hear "4 vocabularies of type chemical shown." (or "All 49 vocabularies shown.") through
`#__live-status`, 500 ms after the last change.

The script relies on the order in which the hook writes each group: `##` category, optional
`###` group heading, optional shared paragraph, `div.vocab-table`. The selftest cannot check the
script, so after changing that order, check the filter in a browser.

## Updating the font

The woff2 files come from the `@fontsource-variable/dm-sans` npm package (`files/*-wght-*.woff2`),
which repackages the Google Fonts build of DM Sans:

    npm pack @fontsource-variable/dm-sans && tar -xzf fontsource-variable-dm-sans-*.tgz
    cp package/files/dm-sans-latin{,-ext}-wght-{normal,italic}.woff2 theme/fonts/
    cp package/LICENSE theme/fonts/OFL.txt
